Metrics

VAULT labels, 14 recording rules, and raw OpenBao metrics used by the monitoring dashboard.

This page distinguishes raw OpenBao telemetry from recording metrics evaluated by vmalert. files/victoria/rules/vault.yml defines 14 recording rules. Their results are not available from /v1/sys/metrics.

Raw metrics vary with OpenBao version, member role, and runtime state. The metrics below are those used by Vault Overview and its rules, not the full telemetry output. See OpenBao telemetry metrics for the complete list.

VAULT metrics use these labels:

Recording rules use vault:ins:* for instances and vault:cls:* for clusters.

Raw Metric Behavior

OpenBao retains Vault’s vault_ prefix and exports Prometheus metrics through go-metrics. Note:

  • Counters lack a _total suffix, for example vault_raft_apply and vault_token_creation.
  • Summaries use milliseconds: quantiles and _sum for vault_core_handle_request are in milliseconds. Recording rules divide average latency by 1,000 to convert it to seconds.
  • Some counters appear only after their first event, such as vault_audit_log_request_failure. Rules use increase_pure to count increases from zero.
  • Only the leader reports Autopilot and follower metrics. They persist for 24 hours after it steps down (prometheus_retention_time). Rules use only the current active member’s values and map node_id / peer_id back to ins.
  • Usage gauges (tokens, KV secrets, identity entities) are computed every ten minutes (usage_gauge_period).

Recording Rules

Expressions preserve source semantics. ins and cls indicate instance and cluster aggregation; actual retained labels follow the by and vector-matching clauses.

Recording MetricDescriptionExpression
vault:ins:req_rpsNon-login requests per second per instancerate(vault_core_handle_request_count{job="vault"}[1m])
vault:ins:login_rpsLogin requests per second per instancerate(vault_core_handle_login_request_count{job="vault"}[1m])
vault:ins:req_rt_avg_5mFive-minute mean instance request latency, in secondsrate(vault_core_handle_request_sum{job="vault"}[5m]) / rate(vault_core_handle_request_count{job="vault"}[5m]) / 1000
vault:cls:req_rt_avg_5mFive-minute mean cluster request latency, weighted by request volume, in secondssum by (job,cls) (rate(vault_core_handle_request_sum{job="vault"}[5m])) / sum by (job,cls) (rate(vault_core_handle_request_count{job="vault"}[5m])) / 1000
vault:cls:unsealedNumber of unsealed cluster memberssum by (job,cls) (vault_core_unsealed{job="vault"}) or (0 * count by (job,cls) (up{job="vault"}))
vault:cls:activeNumber of active cluster members; normally exactly onesum by (job,cls) (vault_core_active{job="vault"}) or (0 * count by (job,cls) (up{job="vault"}))
vault:cls:autopilot_healthyCluster health as reported by the active membermax by (job,cls) (vault_autopilot_healthy{job="vault"} and on(ins) (vault_core_active{job="vault"} == 1))
vault:cls:failure_toleranceCluster fault tolerance as reported by the active membermax by (job,cls) (vault_autopilot_failure_tolerance{job="vault"} and on(ins) (vault_core_active{job="vault"} == 1))
vault:ins:autopilot_healthyMember health as reported by the active membermax by (job,cls,ins) (label_replace(vault_autopilot_node_healthy{job="vault"} and on(ins) (vault_core_active{job="vault"} == 1), "ins", "$1", "node_id", "(.+)"))
vault:ins:raft_lagNumber of log entries by which a follower’s applied index trails the leadermax by (job,cls,ins) (label_replace(vault_raft_storage_follower_applied_index_delta{job="vault"} and on(ins) (vault_core_active{job="vault"} == 1), "ins", "$1", "peer_id", "(.+)"))
vault:ins:raft_heartbeat_msMilliseconds since the follower’s last heartbeatmax by (job,cls,ins) (label_replace(vault_raft_storage_follower_last_heartbeat_ms{job="vault"} and on(ins) (vault_core_active{job="vault"} == 1), "ins", "$1", "peer_id", "(.+)"))
vault:ins:audit_failure_5mAudit write failures per instance over five minutessum by (job,cls,ins,ip,instance) (increase_pure({__name__=~"vault_audit_log_(request|response)_failure",job="vault"}[5m]))
vault:ins:backup_timeUnix timestamp of the instance’s latest successful snapshotmax by (ip) (vault_backup_last_success_timestamp_seconds) + on(ip) group_right() vault_up * 0
vault:ins:backup_sizeSize of the instance’s latest successful snapshot, in bytesmax by (ip) (vault_backup_size_bytes) + on(ip) group_right() vault_up * 0

With no requests in a time window, average latency is 0/0 = NaN, which is discarded and appears as no data.

vault_up comes from INFRA’s shared aliveness rules, based on up{job="vault"}. It is not counted among the module’s rules. It indicates scrape success, not whether a member is unsealed or serving requests.
