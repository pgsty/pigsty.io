Metrics

Metric endpoints, labels, recording rules, and queries for INFRA Victoria observability components.

INFRA monitors VictoriaMetrics, VictoriaLogs, VictoriaTraces, VMAlert, Alertmanager, Grafana, Nginx Exporter, and Blackbox Exporter. Targets come from roles/infra/templates/prometheus/infra.yml.j2; scrape jobs are defined in roles/infra/templates/victoria/prometheus.yml.

Component versions and enabled services affect the raw metric set. This page lists scrape targets, rules, and common metrics for the Victoria stack. See Monitoring System for site-wide counts.

Metric Definitions and Counts

  • Raw metrics: Produced by components or exporters. Read TYPE and HELP at /metrics for their types and meanings.
  • Recorded metrics: Computed from expressions by vmalert and queried in VictoriaMetrics. They have no independent TYPE metadata and cannot all be classified as Counter or Gauge.
  • Scrape status: up and scrape_* are generated by the collection system. up=1 indicates a successful scrape; database and application availability still require functional checks.

Histogram / Summary _bucket, _sum, and _count are different samples of the same metric family. Historical table rows, recording rules, and live time series count different objects and cannot be added together.

Current Recording Rules

files/victoria/rules/infra.yml defines 2 recording rules, evaluated by vmalert and written back to VictoriaMetrics:

MetricSource ExpressionMeaning
infra_upup{job="infra"}Whether an infrastructure scrape endpoint is reachable
agent_upup{job!~"infra|node|etcd|minio|pgsql|redis|mysql"}Reachability of targets outside the excluded jobs

infra_up and agent_up are recording rules, absent from components’ raw /metrics output. The exclusion list above defines the scope of agent_up: it does not exclude jobs such as kafka, ping, or pgrds, and does not cover exporters already in node or pgsql. up=1 indicates only successful scraping. Assess functional service health with nginx_up, probe results, or component metrics.

The InfraDown and AgentDown alerts fire when their respective metrics stay below 1 for one minute. Both use severity CRIT. See Monitoring and Alerting for the rules.

Get the Actual Metric List

Run these queries in VictoriaMetrics VMUI (default http://<infra-ip>:8428/vmui) or Grafana Explore:

up{job="infra"}
count by (cls) (up{job="infra"})
count by (__name__) ({job="infra"})

The first query checks each target’s scrape status, the second counts registered component endpoints, and the third lists visible series counts by metric name at the query time. To count distinct metric names, use count(count by (__name__) ({job="infra"})). This is still not an exporter metric-family count and cannot be added directly to other module counts.

Read raw types, HELP text, and labels from the target endpoint, for example:

curl -fsS http://127.0.0.1:8428/metrics
curl -fsS http://127.0.0.1:9428/metrics
curl -fsS http://127.0.0.1:8880/metrics
