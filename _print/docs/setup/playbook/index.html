Run Playbooks with Ansible

Use Ansible playbooks to deploy and manage Pigsty clusters.

Pigsty uses Ansible to deploy and manage clusters. Ansible applies declarative configuration through playbooks. Pigsty module playbooks use idempotent tasks to reach the specified configuration.

For a single-node installation, use deploy.yml. Other built-in playbooks perform specific module operations. Ansible knowledge helps you manage Pigsty, but the single-node procedure does not require it.

Deploy Playbook

The deploy.yml playbook applies the core deployment configuration. It includes the CA, software repository, NODE, INFRA, ETCD, PGSQL, and MINIO when the inventory enables them. Optional modules such as Redis, Kafka, and native MySQL require their own playbooks. Defining these optional modules in the inventory does not add them to deploy.yml.

The table shows the module deployment targets:

PlaybookCommandGroupinfra[nodes]etcdminio[pgsql]
infra.yml./infra.yml-l infra✓✓

You can apply the core configuration in one run with deploy.yml. For deployment in stages, follow the Customization Guide.

Install Ansible

The Pigsty installation script installs Ansible and its dependencies. The offline bootstrap procedure can also install them.

To install Ansible manually, use the command for your operating system. The minimum supported Ansible version is 2.9.

Debian / Ubuntu
sudo apt install -y ansible python3-jmespath
EL
sudo dnf install -y ansible python3.12-jmespath python3-cryptography  # EL 8
sudo dnf install -y ansible python3-jmespath                           # EL 9
sudo dnf install -y ansible                                            # EL 10
MacOS
brew install ansible
pip3 install jmespath
Ansible packages on EL 10

The EL 10 EPEL repository does not yet supply all required Ansible packages. The Pigsty PGSQL repository supplies the additional packages.

On macOS, install Ansible with Homebrew. You can use the Mac as an administration node for remote cloud servers. This method is suitable for personal single-node deployments. For production, use a Linux administration node.

Execute Playbook

Ansible playbooks are executable YAML files with task definitions. Make sure that ansible-playbook is available through your PATH environment variable. The command ./node.yml runs ansible-playbook node.yml.

Use these four arguments to control execution:

PurposeParameterDescription
Target-l|--limit <pattern>Limit execution to specific groups/hosts/patterns
Tasks-t|--tags <tags>Only run tasks with specific tags
Params-e|--extra-vars <vars>Extra command-line parameters
Config-i|--inventory <path>Use a specific inventory file
./node.yml                         # Run node playbook on all hosts
./pgsql.yml -l pg-test             # Run pgsql playbook on pg-test cluster
./infra.yml -t repo_build          # Run infra.yml subtask repo_build
./pgsql-rm.yml -l pg-test -e pg_rm_pkg=false --check # Preflight removal while keeping packages
./infra.yml -i conf/mynginx.yml    # Use another location's config file

Limit Hosts

Use -l|--limit <selector> to select the target hosts or groups. The selector can contain an IP address, group name, or pattern.

./pgsql.yml                              # Run on all hosts (dangerous!)
./pgsql.yml -l pg-test                   # Run on pg-test cluster
./pgsql.yml -l 10.10.10.10               # Run on single host 10.10.10.10
./pgsql.yml -l pg-*                      # Run on hosts/groups matching glob `pg-*`
./pgsql.yml -l '10.10.10.11,&pg-test'    # Run on 10.10.10.11 in pg-test group
./pgsql-rm.yml -l 'pg-test,!10.10.10.11' --check # Preflight removal; verify target and backups before execution

See the Ansible host and group patterns for the selection rules.

Select the target hosts

Most playbooks target all applicable inventory hosts if you omit --limit. Specify the target before you run a playbook that changes an existing deployment.

Limit Tasks

Use -t|--tags <tags> to select tasks by tag. This limits execution to the selected tasks instead of the complete playbook:

./infra.yml -t repo          # Create repo
./node.yml  -t node_pkg      # Install node packages
./pgsql.yml -t pg_install    # Install PG packages and extensions
./etcd.yml  -t etcd_config   # Render ETCD configuration again
./minio.yml -t minio_alias   # Write the mcli client alias

To select multiple tags, separate them with commas:

./node.yml  -t node_repo,node_pkg   # Add repos, then install packages
./pgsql.yml -t pg_hba,pg_reload     # Configure, then reload pg hba rules

Extra Vars

Use -e|--extra-vars KEY=VALUE to override configuration parameters for one run. These variables have the highest variable precedence. You can supply -e more than once:

# Create admin using another admin user
./node.yml -e ansible_user=admin -k -K -t node_admin

# Initialize a specific Redis instance: 10.10.10.11:6379
./redis.yml -l 10.10.10.10 -e redis_port=6379 -t redis

# Remove PostgreSQL but keep packages and data
./pgsql-rm.yml -l pg-test -e pg_rm_pkg=false -e pg_rm_data=false --check

For lists, objects, or multiple variables, supply a JSON string:

# Add repo and install packages
./node.yml -t node_install -e '{"node_repo_modules":"infra","node_packages":["duckdb"]}'

Specify Inventory

The default inventory is pigsty.yml in the Pigsty source directory. Use -i <path> to select a different inventory file:

./pgsql.yml -i conf/rich.yml            # Initialize single node with all extensions per rich config
./pgsql.yml -i conf/ha/full.yml         # Initialize 4-node cluster per full config
./pgsql.yml -i conf/app/supa.yml        # Initialize 1-node Supabase deployment per supa.yml
Change the default inventory

To change the default permanently, edit inventory in ansible.cfg.

Convenience Scripts

The bin/ directory contains scripts for common operations. Each script calls an Ansible playbook with the necessary arguments:

bin/node-add   <cls>            # Add nodes to Pigsty management: ./node.yml -l <cls>
bin/node-rm    <cls>            # Remove nodes from Pigsty: ./node-rm.yml -l <cls>
bin/pgsql-add  <cls>            # Initialize PG cluster: ./pgsql.yml -l <cls>
bin/pgsql-rm   <cls>            # Remove PG cluster: ./pgsql-rm.yml -l <cls>
bin/pgsql-user <cls> <username> # Add business user: ./pgsql-user.yml -l <cls> -e username=<user>
bin/pgsql-db   <cls> <dbname>   # Add business database: ./pgsql-db.yml -l <cls> -e dbname=<db>
bin/redis-add  <cls>            # Initialize Redis cluster: ./redis.yml -l <cls>
bin/redis-rm   <cls>            # Remove Redis cluster: ./redis-rm.yml -l <cls>

Use these scripts when their operation matches your task.
