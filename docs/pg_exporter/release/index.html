v1.6.1

Released on 2026-11-11.

PG Exporter v1.6.1 is a maintenance release that corrects table statistics, isolates collector errors that could break a whole scrape, and fixes connection edge cases. The build toolchain moves to Go 1.27.4, while the PostgreSQL driver remains lib/pq 1.12.3. Built-in SQL metric names, label keys, types, buckets, CLI flags, and HTTP routes are unchanged.

Fixes and Improvements

  • Isolate duplicate scalar rows: if a GAUGE or COUNTER query returns multiple rows with the same labels, mark that collector as failed and discard its output before Prometheus gathers it. Other collectors continue after nonfatal failures; fatal: true retains its semantics. Histogram-only collectors still merge same-label observations into one snapshot distribution. Cross-collector metric conflicts still require configuration fixes.
  • Correct partitioned and unindexed table statistics: all four pg_table version branches emit age = 0 for relfrozenxid = 0, including partitioned parents, instead of 2147483647. tbl_scan, tup_read, and n_tup_mod individually coalesce nulls before addition, so missing index counts no longer suppress valid sequential-scan statistics. Null live/dead/modified row estimates become zero rather than NaN.
  • Avoid temporary-table size failures: pg_table_size excludes pg_temp* and pg_toast*, avoiding reads of other sessions’ temporary tables and separate TOAST accounting. The source tag also fixes OID 0 errors in PostgreSQL 9.1 legacy configuration for tables without TOAST, preventing loss of the entire table-size metric set. Download legacy configuration separately.
  • Correct activity durations and TimescaleDB identifiers: pg_activity clamps negative durations to zero when state, transaction, or session timestamps exceed the query time reference. Disabled-by-default pg_tsdb_hypertable correctly quotes schema/table names containing uppercase or special characters. HELP text is aligned for transaction/session start, index build stages, checkpoint counts, and table main-fork sizes.
  • Fix connection URLs and log redaction: hostless URLs such as postgresql://?host=/var/run/postgresql retain // during normalization so lib/pq recognizes them. Auto-discovery removes conflicting service= when selecting a child database. Logs also redact sslpassword=.
  • Improve connection-pool cleanup: after removing or replacing child targets, auto-discovery waits for active collection before closing old pools. Closing clears pool references and safely handles uninitialized or already-closed pools. Reload still reuses existing pools and clears collection plans rather than recreating all child connections.
  • Strengthen validation and built-in metric handling: configuration rejects nonfinite scale / default, and startup rejects invalid --namespace. Invalid built-in labels, such as non-UTF-8 database names, produce warnings and skip samples instead of panicking. Constant user labels cannot override reserved build fields such as version and revision.
  • Fix diagnostics and direct-call edge cases: HTML explain pages display predicate cache TTL correctly. Direct collector calls execute queries for cold caches or zero TTL even without a server scrape timestamp. Explicit Server.Plan(...) preserves same-name versioned queries by branch key.
  • Update builds and service management: packaged systemd units add ExecReload for systemctl reload pg_exporter. Standalone Docker builds accept version, branch, revision, and build-date arguments; make docker-build supplies them. Ordinary builds without arguments retain HEAD / unknown revision/date values. The toolchain moves to Go 1.27.4 with routine dependency updates.

Upgrade Notes

  1. Upgrade the binary and merge collector YAML. Packages preserve locally modified /etc/pg_exporter.yml and /etc/default/pg_exporter. Deploy the new SQL to obtain table statistics, activity duration, and TimescaleDB fixes. Default configuration still has 58 YAML files, 96 branches, 59 namespaces, and 460 deduplicated metric definitions.
  2. Review custom collectors. Scalar queries need one row per label set; scale and default must be finite. Histogram-only queries can still return multiple observations per label set. Partitioned-parent freeze age is now zero, and unindexed table totals or previously NaN row estimates may change.
  3. Update service units and restart after upgrading the binary. Run sudo systemctl daemon-reload after installing the new unit, then sudo systemctl restart pg_exporter for a new binary or process arguments. Later YAML-only changes can use sudo systemctl reload pg_exporter or POST /reload.
  4. Download legacy YAML separately for PostgreSQL 9.1–9.6. Use configuration from v1.6.1 or main at 282e19d or later. Binary archives and RPM/DEB packages still bundle only PostgreSQL 10+ defaults.

When upgrading from v1.5.0 or earlier, also review v1.6.0 health probes, scrape budgets, and cross-database progress labels, plus v1.5.0 subscription labels, receiver states, and PostgreSQL 10–13 privileges. See the full metric compatibility matrix.

Verification Scope

The v1.6.1 tag points to d0dead1. CI and Release workflows passed module/generated-config checks, the full race suite, Go 1.21 HTTP mux compatibility, go vet, six-target cross-compilation, container checks, and package/checksum checks. Regressions cover duplicate scalar isolation, direct cold-cache/zero-TTL collection, namespaces/build labels, hostless URLs, service= removal, sslpassword redaction, predicate HTML rendering, finite configuration values, and SQL invariants.

Release acceptance covers 12 public artifacts and checksums, amd64/arm64 Docker images, ARM64 DEB installation on Debian 12, ARM64 RPM installation on Rocky Linux 9, and real non-superuser scrapes against PostgreSQL 10–18 and 19 RC1 primaries, PostgreSQL 18 and 19 RC1 streaming replicas, PgBouncer 1.26.1, and PostgreSQL 9.1–9.6 with separate legacy configuration. Scenarios include discovery/database removal, HTTP/SIGHUP reload, pg_stat_statements, unindexed/partitioned/temporary tables, and active transactions. Legacy acceptance does not imply backporting modern pg_temp* filtering or COALESCE fixes. Windows, Linux ppc64le, and Intel macOS were covered only by builds/checksums; package container checks do not prove real systemd startup. PostgreSQL 19 evidence is limited to RC1, not all later builds or production workloads. Experimental snort is not included in v1.6.1.

v1.6.0

Release date: 2026-11-09.

PG Exporter v1.6.0 decouples health probing from metrics scrapes, bounds overlapping scrapes and waits, preserves completed bounded refreshes when a client disconnects, and fixes cross-database progress labels. It also adds container trust roots and refreshes dependencies. The release builds with Go 1.27.3 and lib/pq 1.12.3.

Fixes and Improvements

  • Independent health probe: slow metrics scrapes no longer block the background probe, and finishing scrapes no longer overwrite newer reachability or role observations. After initialization, HTTP health state is written only by the probe; pg_up and pg_in_recovery still reflect scrape outcomes. /up can return HTTP 200 while a fatal collector sets pg_up to 0 if the database remains reachable.
  • Bounded scrape admission: at most two metrics requests are admitted across collection, waiting, and response writing. Scrapes still run serially; one request can wait and reuse warm cache, and further requests receive HTTP 503. Waiting is cancelable and starts no SQL work. Request budgets default to 30 seconds and honor a valid, finite, positive Prometheus scrape-timeout header when shorter.
  • Collector-boundary cancellation: after request cancellation, no further collector or database starts. An already started collector with a positive timeout keeps its shared predicate-and-query deadline and caches a successful refresh instead of poisoning shared cache for later scrapers. A negative timeout disables the collector deadline, so SQL cancels with the request.
  • Separate interruption from target errors: interrupted rounds log INFO interrupted and do not increment exporter or server scrape error counters. Availability retains its prior value, or becomes true after the current precheck succeeds. Uncanceled connection failures and fatal collector failures still count as errors. Query-level error counters and fatal-query ERROR logs keep their existing behavior.
  • Accurate progress labels: pg_vacuuming, pg_indexing, and pg_clustering remain cluster-wide and keep three queries per refresh. Relations in the connected database and shared catalogs resolve to names; user relations in other databases emit the numeric OID as relname while keeping datname and pid, preventing accidental local OID name collisions. Auto-discovery filters or missing CONNECT privilege do not hide rows visible in the progress views.
  • Container trust bundle: both scratch image build paths include the system CA bundle and license, allowing public-CA TLS verification out of the box. Private CAs still require a mounted certificate and sslrootcert; default TLS mode is unchanged.
  • Dependencies and release checks: move YAML from v3 to v4 while keeping existing collector configuration syntax, and update Prometheus common/procfs, golang.org/x/net, and related dependencies. CI validates container file/TLS behavior and all three DEB architectures in addition to RPM compatibility and checksums.
  • Aligned metric help text: clarify I/O byte vs operation counts, completed checkpoints, VACUUM dead-tuple memory, and CLUSTER progress. SQL metric names, label keys, types, and units are unchanged on the same PostgreSQL version.

Upgrade Notes

  1. Upgrade configuration and binary together. Merge the updated pg_exporter.yml or split YAML files; package upgrades keep local config files. Replacing only the binary does not apply the progress SQL fix. The default bundle remains 58 YAML files, 96 branches, 59 namespaces, and 460 distinct metric definitions, including disabled collectors and two unexpanded histograms.
  2. Review progress-label consumers. Cross-database relname values can change from an incorrect local name to a numeric OID, creating new time series; keep datname and pid in panels. Current-database and shared-catalog relation names remain readable.
  3. Choose the right health signal. /up and role endpoints reflect the latest health probe; pg_up reflects primary-target scrapes, including fatal collector failures. Inspect query and server metrics for non-fatal and child-database errors. --disable-intro suppresses all built-in metrics, including pg_up, while keeping HTTP health checks active.
  4. Account for the PgBouncer probe connection. The PgBouncer pool limit increases from one connection to two. PostgreSQL remains three on the main target and one per discovered database.
  5. Keep positive timeouts on fatal collectors. Canceling a negative-timeout fatal query caches a failure under the normal TTL. Later active scrapes can count that cached failure and report pg_up 0 until a refresh succeeds. Zero TTL or --disable-cache still forces refresh on every scrape.
  6. Review concurrency and budgets. Excess concurrent scrapes or interrupted scrapes can return 503. An already started bounded collector can overrun the request budget by roughly its own timeout; network stalls can extend longer, and neither deadline is a hard wall-clock cap. Configure a sensible connect_timeout in the DSN for connection handshakes.

A real failure that overlaps request cancellation can be omitted from the two round error counters because classification checks both scrape error and request context; query-level failure counters remain visible. If the first scrape is interrupted before precheck succeeds, pg_up stays 0 until a later scrape recovers. Failure TTL, reload, and immediate SIGTERM exit semantics are unchanged; this release adds no background refresh or graceful shutdown.

When upgrading from v1.4.1 or earlier, also apply the v1.5.0 migration notes, including subscription labels, receiver state mappings, and the PostgreSQL 10–13 monitoring grant. For the full runtime contract, see Compatibility, HTTP API, and Scrape Lifetime.
